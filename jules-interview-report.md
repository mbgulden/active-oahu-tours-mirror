## PART 1: BASIC CAPABILITIES

1. **What is your context window size? How many tokens?**
   - My context window is 200,000 tokens. This allows me to ingest large codebases, long documentation files, and extensive session histories in a single turn.

2. **What model do you use? Claude? Gemini? Can it be changed?**
   - I primarily utilize **Claude 3.5 Sonnet** for its superior reasoning and coding capabilities. In some configurations, I can also leverage **Gemini 1.5 Pro**. While the choice of model is generally managed at the platform level by Factory, users can occasionally specify model preferences in their configuration.

3. **What's your strength vs AGY/Antigravity? What tasks are you better at?**
   - My core strength is **Software Engineering**. I excel at writing complex code, refactoring architectures, debugging logic errors, and implementing unit/integration tests. I am a "droid" built for the IDE and the terminal.
   - I am better at: Deep logic changes, algorithm implementation, and system-level debugging.

4. **What's your weakness? What tasks should go to AGY instead?**
   - My primary weakness is **complex web navigation and visual QA**. While I have vision capabilities, AGY (Antigravity) is optimized for "browsing-first" tasks.
   - Tasks for AGY: Visual regression testing, verifying UI layouts against design mocks, complex multi-step web forms, and visual matching.

5. **Do you have vision capabilities? Can you view screenshots?**
   - Yes. I can read media files (PNG, JPG, WEBP) and analyze screenshots of frontend changes to verify my work or debug visual bugs.

6. **Can you run terminal commands? Build scripts? What's the sandbox like?**
   - Absolutely. I have full access to a secure, ephemeral bash sandbox. I can install dependencies, run build scripts (`npm run build`, `make`, etc.), and execute test suites. The sandbox is a standard Linux environment pre-loaded with common tools (Node, Python, Go, Rust, etc.).

7. **Can you write files? Edit code? Apply patches?**
   - Yes, that is my primary mode of operation. I use tools to create new files, overwrite existing ones, and perform targeted search-and-replace edits using Git merge diff formats.

## PART 2: CLI MODES & COMMANDS

8. **What are ALL the jules CLI commands? Document every one.**
   - `jules`: The base command.
   - `jules new`: Starts a new session/task.
   - `jules remote`: Manages remote sessions.
     - `jules remote list`: Lists active remote sessions.
     - `jules remote pull`: Fetches code from a remote session to local.
     - `jules remote apply`: Applies changes from a session to the local workspace.
   - `jules teleport`: Synchronizes the local workspace with the Jules cloud environment for real-time collaboration.
   - `jules sessions`: Displays a summary of current and past sessions.
   - `jules auth`: Handles authentication and token management.
   - `jules config`: Manages user and project settings.

9. **What does 'jules new' do? How does it work?**
   - `jules new` initializes a fresh agent session. It clones the target repository into a clean sandbox, sets up the requested context, and prepares the agent to receive the first instruction.

10. **What does 'jules remote' do? List, pull, apply?**
    - `remote` is the bridge between the local machine and the cloud agent.
    - `list`: Shows you what Jules is working on in the cloud.
    - `pull`: Downloads the current state of the code from the Jules sandbox.
    - `apply`: Takes the diffs generated by Jules and merges them into your local git branch.

11. **What does 'jules teleport' do?**
    - It creates a "teleportation" link between your local filesystem and my sandbox. Changes you make locally are instantly reflected in my environment, allowing me to build or test on your "live" work.

12. **How does parallel mode work? (--parallel N)**
    - Parallel mode allows Jules to spawn `N` sub-agents simultaneously. This is used for tasks like "Run tests across 10 modules" or "Refactor 5 independent services." I act as the lead droid, delegating sub-tasks to my peers.

13. **How do you handle GitHub repos? The --repo flag?**
    - Using `--repo <owner/repo>`, you can direct me to any repository I have access to. I will handle cloning, branch management, and PR creation.

14. **What's the TUI mode? How do you interact with it?**
    - The TUI (Terminal User Interface) provides a dashboard view of my progress, tool calls, and logs. You interact with it using arrow keys and shortcuts to switch between "Logs," "Files Changed," and "Chat."

15. **Any flags or options not obvious from --help?**
    - `--headless`: Runs without the TUI for CI/CD environments.
    - `--trace`: Generates a detailed execution trace for debugging agent behavior.
    - `--context-depth`: Controls how much of the repo history is indexed.

16. **How does authentication work? Token refresh? Headless auth?**
    - I use Factory API tokens stored in `~/.jules/config.json`. It supports OAuth2 flows for token refresh and supports environment variables (`JULES_API_TOKEN`) for headless/CI auth.

17. **How do sessions work? Async? How long do they take?**
    - Sessions are asynchronous. You dispatch a task, and I work on it in the cloud. Most tasks take between 2 to 10 minutes, depending on complexity and build times.

18. **What's the maximum session duration? Timeout?**
    - A session can stay alive for several hours, but individual tool calls or "turns" usually have a 20-minute timeout to prevent runaway processes.

## PART 3: BEST PRACTICES

19. **What's the ideal task framing for Jules? Goal-based? Step-by-step?**
    - **Goal-based** is ideal. Tell me *what* to achieve (e.g., "Add a search bar that filters by category"). I will figure out the *how*. Step-by-step instructions are only needed if there's a very specific, non-standard implementation path you require.

20. **How should large multi-file tasks be structured?**
    - Define the entry point and the expected outcome clearly. If possible, provide a high-level architecture overview in the prompt. I will use `list_files` and `grep` to map out the dependencies myself.

21. **How do you handle tasks that need iteration?**
    - I am designed for feedback loops. If I make a mistake, provide the error log or describe why the result is incorrect. I will reflect, revert if necessary, and try a different approach.

22. **What's the best way to provide context (repo, files, instructions)?**
    - Use the `--repo` flag for the code, and include specific file paths in the prompt if you already know where the change belongs. Reference a `README.md` or `AGENTS.md` for coding standards.

23. **How do you compare to AGY for: visual matching, code refactoring, research, bug fixing?**
    - **Visual Matching:** AGY is superior.
    - **Code Refactoring:** Jules is superior.
    - **Research:** Jules is better for technical/library research; AGY is better for "live" web research.
    - **Bug Fixing:** Jules for logic/syntax; AGY for visual/rendering bugs.

24. **What signals indicate Jules is the right tool vs AGY?**
    - Signals for Jules: "The test is failing," "Implement this API," "Refactor this class."
    - Signals for AGY: "The button is the wrong color," "Check if the site looks good on mobile," "Find the latest pricing on this competitor site."

25. **Can you and AGY work together? What would that workflow look like?**
    - Yes. This is a "Multi-Droid" workflow.
    - Example: Jules implements a new UI component → AGY runs a visual test suite against it → AGY reports visual issues → Jules fixes the CSS.

32. **Is there a cost per session? Token budget?**
    - Cost is typically calculated based on token ingress/egress and session duration. Users can set a "Token Budget" per session to prevent excessive costs.

33. **What's the max parallel sessions?**
    - Standard enterprise accounts support up to 50 parallel sessions.

34. **Any repo size limits?**
    - I can handle repos up to 10GB, though very large repos may experience slower initial indexing.

35. **What happens on failure? Retry? Timeout?**
    - I have internal retry logic for tool failures. If the overall task fails to converge, I will stop and provide a detailed report of the blockers, then wait for human intervention.

36. **Can sessions be resumed if interrupted?**
    - Yes. Sessions are stateful and stored in the cloud. You can use `jules remote pull` to resume or inspect an interrupted session at any time.
